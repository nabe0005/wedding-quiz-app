# AI未来予測 投票アプリ — セットアップ手順書

## 0. 全体像

- `index.html` … 参加者用（スマホでQR経由アクセス）
- `host.html` … 司会者用（パスワード保護、進行操作・集計・正解ランキング・削除）
- `css/style.css` … 共通デザイン（クイズ番組風のポップなテーマ）
- `js/firebase-config.js` … Firebaseの接続設定（自分の値に書き換える）
- `database.rules.json` … Firebase Realtime Databaseのセキュリティルール

料金：Firebase無料プラン（Spark）の範囲内で、40〜50人・数十分の利用なら十分に収まります。

### 主な機能（改訂版）
- 問題数は固定ではなく、司会者画面の「＋ 問題を追加」「× 削除」で自由に増減できます（過去・現在・未来など、好きな数だけ作成可能）
- 各問題に「正解」を1つ設定できます（過去・現在クイズ向け）。「正解なし」も選べるので、未来予想のような答えのない問題も作れます
- 「結果を公開」を押すと、正解の選択肢が★マーク付きでハイライトされます
- 景品抽選の代わりに「正解ランキング」機能があり、参加者の正解数で順位（🥇🥈🥉）を表示します

## 1. Firebaseプロジェクトの作成

1. https://console.firebase.google.com/ にアクセスし、Googleアカウントでログイン
2. 「プロジェクトを追加」→ プロジェクト名を入力（例：`wedding-quiz`）→ Googleアナリティクスは「無効」でOK → 作成
3. 左メニュー「構築」→「Realtime Database」→「データベースを作成」
   - ロケーションは `asia-southeast1`（シンガポール）など近いリージョンを選択
   - セキュリティルールは「ロックモード」でいったん作成（後で置き換えます）
4. 左メニュー「構築」→「Authentication」→「Sign-in method」タブ →「匿名」を有効化

## 2. Webアプリの登録と設定値の取得

1. プロジェクトの概要画面 →「</>」（ウェブ）アイコンをクリックしてアプリを追加
2. アプリのニックネームを入力（例：`quiz-app`）→ Firebase Hostingは今はチェック不要 → アプリを登録
3. 表示された `firebaseConfig` の値（apiKey, authDomain, databaseURL など）をコピー
4. `js/firebase-config.js` を開き、`firebaseConfig` の中身を実際の値に書き換える

## 3. 司会者パスワードの設定

1. Firebaseコンソール →「Realtime Database」→ データタブを開く
2. ルート直下に `adminConfig` というキーを手動で追加し、その子に `password` というキーで好きな文字列（例：`kekkon2027`）を入力して保存
   - これが司会者画面のログインパスワードになります
   - 参加者・ゲストがこの値を読み取ることはできません（ルールで `.read: false` にしているため）

## 4. セキュリティルールの適用

1. Firebaseコンソール →「Realtime Database」→「ルール」タブを開く
2. `database.rules.json` の中身を全てコピーし、コンソールのルール欄に貼り付けて「公開」をクリック

## 5. デプロイ（公開）方法

初心者向けにコマンド操作の少ない **GitHub Pages** を推奨します（Firebase Hostingを使う場合は下記に補足あり）。

### GitHub Pagesの場合
1. GitHubで新しいリポジトリを作成（例：`wedding-quiz-app`）
2. `index.html`, `host.html`, `css/`, `js/` フォルダをそのままアップロード
3. リポジトリの「Settings」→「Pages」→ Branch を `main` / `/(root)` に設定して保存
4. 数分後、`https://ユーザー名.github.io/wedding-quiz-app/` でアクセス可能になります
5. 参加者用URLは `.../index.html`、司会者用は `.../host.html`

### Firebase Hostingの場合（参考）
```
npm install -g firebase-tools
firebase login
firebase init hosting   # publicディレクトリをこのフォルダに指定
firebase deploy
```

## 6. QRコードの作成

- 参加者用URL（`index.html`）をQRコード生成サイト（例：https://www.qr-code-generator.com/ ）に貼り付けて画像を作成
- 印刷したものを各テーブルに置く、またはスクリーンに映しておく
- 司会者用URL（`host.html`）はQR化せず、操作担当の人だけが知っていればOK

# テスト手順（本番前に必ず実施）

## A. ローカル動作確認
1. パソコン上でこのフォルダを開き、簡易サーバーを起動
   ```
   # Pythonがある場合
   python3 -m http.server 8000
   ```
2. ブラウザで `http://localhost:8000/host.html` を開き、パスワードでログインできるか確認
3. 別ブラウザ（またはスマホ）で `http://localhost:8000/index.html` を開き、参加〜投票できるか確認
   - ※ ローカルの場合、スマホからは同一Wi-Fi内でPCのIPアドレス（`http://192.168.x.x:8000/`）でアクセスします

## B. デプロイ後の複数端末テスト
1. デプロイ後のURLで、実機のスマホ3〜5台程度で同時に参加してみる
2. 1人が同じ問題に2回投票しようとして拒否されることを確認（再読み込みしても投票し直せないこと）
3. 司会画面で「投票受付開始→締切→結果公開→次の問題へ」を一通り操作し、棒グラフが正しく動くか確認
4. Wi-Fiを一時的に切って再接続し、参加者画面が自動的に復帰するか確認
5. 抽選ボタンを押して当選者が表示され、再度押しても同じ人が当たらないことを確認
6. 「投票データを全削除する」を押し、データが消えることを確認（このテスト後、必ずもう一度動作確認をしてから本番に臨む）

## C. 負荷確認（可能であれば）
- 友人・親族に協力してもらい、10〜15人程度で同時アクセスするリハーサルを1回行う
- 無料プランの同時接続数上限（100接続）に対して40〜50人は十分余裕があります

# 本番当日の運用・バックアップ

## 事前準備
- 会場のWi-Fi状況を確認し、可能であれば操作担当者はスマホのテザリングも予備回線として用意
- 問題文・選択肢は前日までに司会者画面から「保存」しておく
- 司会者用パスワードは操作担当者のスマホのメモ等に控えておく

## トラブル時の対応
| 症状 | 対応 |
|---|---|
| 一部のゲストが投票画面を開けない | QRコードの下に短縮URLも併記しておき、手入力してもらう |
| 通信が不安定で表示が固まる | 参加者側はページを再読み込み（リロード）すれば投票状態が復元されます |
| 司会画面が固まった | 別のスマホ・PCで `host.html` を開き、同じパスワードで再ログインすれば続きから操作可能 |
| 投票数が想定よりずれる | 司会画面の集計はリアルタイム再取得なので、一度「締切」→再度「結果を公開」を押すと再計算されます |

## イベント終了後
1. 司会画面の「投票データを全削除する」を押してデータを削除
2. 必要であれば、Firebaseコンソールの「Realtime Database」からもデータが空になっていることを目視確認
3. しばらく再利用予定がなければ、Firebaseコンソールでプロジェクト自体を削除してもOK（無料枠なので放置しても課金は発生しません）
